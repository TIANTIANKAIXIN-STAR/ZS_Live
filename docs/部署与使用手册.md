# ZS Live 云渲染推流平台 — 部署与使用手册

> 版本：v2.0 ｜ 适用平台：Windows 10/11、Windows Server 2019+（Linux 见附录 D）
> 阅读对象：部署运维人员 + 平台使用者

---

## 一、平台是什么

ZS Live 把 **UE（虚幻引擎）打包程序** 的画面实时推到浏览器：

- 服务端一键启动，UE 实例**离屏渲染**（服务器桌面上不会出现任何窗口）
- 浏览器打开网页即可观看，**鼠标键盘操作实时回传 UE**，像操作本地程序一样
- 超低延迟：基于 WebRTC（WHEP 协议），局域网典型延迟 100~300ms
- 支持多程序、多用户排队、会话管理、嵌入第三方业务系统

```
┌────────────┐   RTMP(视频)   ┌──────────┐   WebRTC/WHEP   ┌─────────┐
│ UE 打包程序 │ ────────────► │ MediaMTX │ ──────────────► │  浏览器  │
│ +StreamForge│               │ 流媒体    │                 │ 观看/操作│
│   插件      │ ◄──────────── │ 调度服务  │ ◄────────────── │         │
└────────────┘  控制通道(WS)   │ (Node)   │   键鼠输入(WS)   └─────────┘
                               └──────────┘
```

## 二、环境要求

| 项目 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11 或 Server 2019+ | 64 位 |
| GPU | NVIDIA 显卡（推荐）+ 最新驱动 | 用 NVENC 硬编码，几乎不占 CPU；无 N 卡也可运行（软编码，性能差） |
| Node.js | 18 或更高（推荐 22 LTS） | https://nodejs.org 下载安装即可 |
| .NET 运行时 | 无需安装 | 启动器为自包含单文件（约 48MB），自带 .NET 运行时 |
| VC++ 运行库 | Visual C++ 2015-2022 x64 | UE 程序运行需要，装过 UE/常见游戏一般已有 |
| 浏览器 | Chrome / Edge 最新版 | 用户侧观看用 |

> **不确定环境是否齐全？** 打开启动器看「环境检查」区，绿勾 = 通过，红叉 = 缺失并附带原因。

## 三、快速部署（3 步，约 5 分钟）

### 方式 A：一键安装包（推荐，最简单）

拿到 `ZSLive-Setup-x.x.x.exe` 后：

1. **双击安装**：选择组件（默认全选）→ 一路下一步，默认装到 `C:\ZS_Live`
   - 「UE 演示程序 Windows 版」：装完即有一个可推流的示例程序
   - 「UE 演示程序 Linux 版」：供拷贝到 Linux 渲染节点部署（见附录 D）
2. 安装程序**自动完成**：Node 运行时（无需系统安装 Node）、防火墙规则（TCP 3100/1935/8890 + UDP 8189）、MediaMTX 配置（自动探测局域网 IP）、`.env`、演示模板播种
3. 装完勾选「启动 ZS Live 启动器」→ 点「一键启动」→ 浏览器访问 `http://本机IP:3100/`

> - 未做代码签名，首次运行 SmartScreen 可能提示「未知发布者」：点「更多信息 → 仍要运行」
> - 默认管理员 `admin / admin123`，首次登录后请修改（见附录 A）
> - 卸载：控制面板/设置 → 应用 → ZS Live；数据库与日志（`server\data`、`logs`）会保留，手动删除目录可彻底清理
> - 安装包构建方法见 `installer/README.md`

以下方式 B 适用于直接拷贝目录部署（无安装包时）。

### 方式 B：拷贝目录部署

### 第 1 步：放置平台文件

把整个 `ZS_Live` 目录拷贝到服务器，例如 `D:\ZS_Live`。目录结构：

```
ZS_Live/
├── launcher/
│   └── ZSLiveLauncher.exe     ← 唯一入口，双击它
├── server/                    ← 调度服务（Node.js，免安装）
│   ├── .env                   ← 端口等配置（一般不用改）
│   └── data/zslive.db         ← 数据库（自动创建）
├── mediamtx/                  ← 流媒体服务（免安装）
│   ├── mediamtx.exe
│   └── mediamtx.yml
├── docs/                      ← 文档
└── UETest/Package/Windows/    ← 示例 UE 程序（可换成你的）
```

### 第 2 步：双击启动器

双击 `launcher/ZSLiveLauncher.exe`：

- 启动器**自动拉起全部服务**（MediaMTX + 调度服务），无需任何命令行
- 所有服务**全部后台无窗口运行**，桌面干干净净
- 「服务状态」区三个电源按钮可单独启停对应服务
- 「环境检查」区有红叉时按提示处理（缺 Node 装 Node，缺防火墙规则点下方按钮）
- 启动失败的详细原因直接显示在下方黑色日志区

> 如需**局域网/公网其他电脑访问**：点启动器底部「添加防火墙规则」（需以管理员身份运行启动器：右键 → 以管理员身份运行）。

### 第 3 步：打开浏览器验证

点启动器上「打开首页」，或浏览器访问 `http://服务器IP:3100/`：

- 看到程序卡片列表（StreamHub 首页）
- 首次使用：点「管理后台」（默认账号 `admin` / `admin123`），在「实例模板」里确认/修改 UE 程序路径
- 回到首页，点程序卡片上的「进入」→ 等待几秒 → 画面出现，鼠标键盘即可操作

**部署完成。** 日常使用就是：双击启动器 → 浏览器打开首页。

## 五、管理后台（首次必配）

浏览器打开 `http://服务器IP:3100/admin`，默认账号 `admin` / `admin123`（登录后请立即在「用户管理」改密码）。

### 5.1 实例模板（一个模板 = 一个可推流的 UE 程序）

表单顶部有**画质预设**下拉（720p30 / 1080p30 / 1080p60 / 2K60 / 4K60，含码率建议值），选中自动填入分辨率/帧率/码率，也可手动改成自定义组合。

| 字段 | 说明 | 示例 |
|---|---|---|
| 模板名称 | 显示在首页卡片上 | 水利孪生场景 |
| 程序描述 | 卡片副标题，可写版本/简介 | v1.2 大坝下游 50km |
| UE 可执行文件路径 | 打包程序的 exe 完整路径 | `D:\MyApp\Binaries\Win64\MyApp.exe` |
| 附加启动参数 | UE 命令行参数，可留空 | `-dx12 -ResX=1920 -ResY=1080` |
| 分辨率 / 帧率 | 推流画面规格 | 1920×1080 @ 30 |
| 码率 (kbps) | 1080p30 建议 8000；局域网可到 20000 | 8000 |
| 音频 | 建议选 **PCMA**（浏览器兼容性最好） | pcma |
| 允许输入 | 勾选后浏览器键鼠才能操作 UE | ✓ |

> **离屏渲染默认开启**（系统设置里可关）：UE 实例在服务器上无窗口后台运行。模板附加参数里显式写 `-RenderOffScreen` 或 `-NoRenderOffScreen` 可按模板覆盖全局设置。

### 5.2 系统设置

页面顶部是**环境配置档**（本机 / 局域网 / 公网 / 弱网）：点「应用此配置档」即可把下方对应项一键调到该环境推荐值（公网/弱网档会自动开启浏览器自适应降档，并提示配置 TURN）。

| 设置 | 默认 | 说明 |
|---|---|---|
| 最大并发实例数 | 3 | 受 GPU 显存/编码器数量限制，1080p 一般每张消费级 N 卡 3~8 路 |
| 默认预热数 | 1 | **模板未单独设置预热数时**的默认值；0 = 默认不预热 |
| 实例空闲回收（秒） | 300 | 空闲实例超时自动关闭释放资源（仅对有预热的模板有意义——无预热模板的实例在会话结束时就已直接回收） |
| 离屏渲染 | 开 | 实例 `-RenderOffScreen` 无窗口运行 |
| 会话超时强制释放（分钟） | 30 | 单个会话最长时长，超时自动释放实例；0 = 不限制。超时前 1 分钟页面会有提示 |
| 待命降载帧率 | 5 | 空闲实例以低帧率推流，省 GPU 与带宽；用户接入瞬间自动恢复满配（引擎渲染帧率同步降低） |
| 待命降载码率 (kbps) | 500 | 空闲实例码率，同上 |
| 浏览器自适应降档 | 关 | 开启后播放器监测丢包率/延迟，网络恶化自动降码率（满配→60%→35% 两档，恢复后自动升回）；公网/弱网配置档会自动开启 |

> **预热数按模板单独设置**：在「实例模板」的编辑表单里，每个模板都有独立的「预热实例数」字段——留空 = 跟随全局默认；0 = 该模板不预热（用户进入时才启动）；数字 = 该模板常驻的空闲实例数。列表页的「预热」列会标明每个模板当前设置（默认 / 不预热 / N 个）。模板保存后立即生效并自动补位预热。
>
> **实例回收规则**：用户关闭推流页面后——不预热的模板（0 或全局默认 0）**实例立即停止回收**，下次进入重新启动（约 20~60 秒）；有预热的模板实例回到资源池待命（待命降载状态），供下一个用户秒进。

> **模板参数的两点自动处理**：① 模板「附加参数」里的 `-log` / `-console` 会被自动剔除（避免服务器桌面弹出 UE 日志黑窗口，日志照常写入 `Saved/Logs/`）；② 实例启动时自动注入 `-fps=<模板帧率>`（引擎级限帧），GPU 利用率与推流帧率匹配，不会出现"一个实例吃满整张卡"的现象。

### 5.3 GPU 监控与多卡配额

管理后台新增「**GPU 监控**」页（需 NVIDIA 显卡 + 驱动，数据来自 nvidia-smi 每 5 秒轮询）：

- **每卡状态卡片**：利用率（进度条，≥60% 黄 / ≥90% 红）、显存占用、温度、该卡绑定的实例列表
- **GPU 配额**：填写 `GPU编号:最大实例数`，多卡逗号分隔。例：`0:3,1:1` 表示 GPU0 最多 3 路、GPU1 最多 1 路，合计 4 路并发
  - 启用后，**每个 UE 实例启动时自动绑定到一张卡**（UE 参数 `-graphicsadapter=N`），优先填剩余配额最多的卡
  - 所有卡配额占满时，新会话自动**转入排队**（与实例池满同待遇），有实例释放后自动补位
  - 留空 = 不绑卡（单卡机器无需配置，行为与旧版一致）
- **模板级绑定**：「实例模板」编辑表单的「GPU 绑定」下拉——自动分配（默认，按配额选卡）/ 不绑卡 / 固定绑定某张卡（适合不同程序对显卡有硬性要求的多卡场景）
- Linux 上绑卡同时注入 `CUDA_VISIBLE_DEVICES`，保证 NVENC 编码器也只使用目标卡

| 场景 | 推荐配置 |
|---|---|
| 单卡（如 RTX 4090） | 配额 `0:3` 或留空均可——配额的好处是后台能直观看到每卡占用 |
| 双卡各 4 路 | 配额 `0:4,1:4`，同时把「最大并发实例数」调到 8 |
| 某模板只能用专业卡渲染 | 模板 GPU 绑定固定到该卡，其余模板自动分配消费卡 |

### 5.4 仪表盘与审计

- **仪表盘**：实例池/会话/MediaMTX/服务概况 + **近 24 小时会话趋势柱状图**（每小时新建会话数，悬停查看明细）
- **节点管理**（集群模式）：worker 节点登记/启停/删除，实时查看每节点实例池、GPU、会话/排队；页面显示 master Token 供 worker 配置
- **审计日志**：管理后台所有关键操作自动留痕——登录（含失败）、模板增删改、系统设置修改、环境配置档应用、实例停止/转空闲、用户增删改、移除排队、节点增删改；含操作者、来源 IP、时间。支持按操作类型过滤和分页，日志保留 90 天自动清理
- 接口：`GET /api/admin/audit-logs?page=1&pageSize=20&action=login`、`GET /api/admin/trend`（24 小时逐时会话数，业务系统可自行拉取做报表）

## 六、用户使用（观看 + 操作）

1. 浏览器打开 `http://服务器IP:3100/`
2. 程序卡片上显示实时状态：**可立即进入**（有空闲实例）/ **启动中** / **需排队**
3. 点「进入」：
   - 有空闲实例 → 几秒内出画面
   - 没有 → 自动排队，页面显示位次和预计等待
4. 画面出现后：
   - **鼠标**：在画面上移动/点击/滚轮 = 直接操作 UE 程序
   - **键盘**：直接按键即可（无需点选画面）；输入框打字时不会被透传
   - 右键菜单已被屏蔽（透传给 UE）
5. 多人同时进入同一程序 = 各自独立实例、互不干扰（一人一台"云电脑"）

## 七、业务系统集成（iframe 嵌入）

把推流画面嵌入你自己的网页/系统：

```html
<iframe src="http://服务器IP:3100/embed?template=1&streamId=view-a"
        style="width:100%;height:100%;border:0" allow="autoplay"></iframe>
```

父页面如需与 UE 双向通信（发指令、收事件、同页多路画面），引入 SDK：

```html
<script src="http://服务器IP:3100/sdk/zslive-parent.js"></script>
<script>
  const stream = ZsLive.mount({
    container: document.getElementById('view'),
    server: 'http://服务器IP:3100',
    template: 1,
    streamId: 'view-a',
  });
  stream.on('streaming', () => console.log('画面已出'));
  stream.camera('config', { fov: 90 });        // gameAPI 风格调用
  stream.command('startSimulation', '{}');      // 发指令给 UE
</script>
```

- 接口文档：`GET /api/embed?template=1` 返回完整协议说明
- 消息码表：`GET /api/stream-codes`（错误码与消息码全集）
- 在线演示：`http://服务器IP:3100/integration-demo.html`（含同页双路画面示例）

## 八、网络部署方案

### 8.1 端口一览

| 端口 | 协议 | 用途 | 局域网 | 公网 |
|---|---|---|---|---|
| 3100 | TCP | 网页 + API + 控制通道 | 必开 | 必开（建议反代 HTTPS） |
| 1935 | TCP | UE → MediaMTX RTMP 推流（服务器内部） | 不必对外开放 | 不必对外开放 |
| 8890 | TCP | WHEP 播放信令 | 必开 | 必开 |
| 8189 | UDP | WebRTC 媒体传输 | 必开 | 必开 |

单机部署时 1935 只在服务器内部使用，无需对外开放。

### 8.2 局域网部署（最常见）

1. 启动器点「添加防火墙规则」（管理员身份）
2. 用户浏览器访问 `http://服务器IP:3100/`
3. 完成。无需任何其他配置。

### 8.3 公网部署

**第 1 步：后台一键检测。** 管理后台 →「系统设置」→ 顶部「公网接入检测」→ 点「开始检测」。平台自动探测出口公网 IP，并生成：

- 检查清单（PUBLIC_HOST 是否指向公网、配置档/自适应降档建议、防火墙端口表）
- **coturn（TURN 服务器）一键启动命令**（Docker，复制执行即可）
- **MediaMTX ICE 配置片段**（追加到 `mediamtx/mediamtx.yml` 末尾，重启 MediaMTX）

**第 2 步：放行端口。** 防火墙/安全组放行：TCP `3100 / 8890 / 3478`，UDP `8189 / 49160-49200`（TURN 中继区间）。1935 不必对外开放。

**第 3 步：修正对外地址。** `server/.env` 里 `PUBLIC_HOST=公网IP` 后重启；`mediamtx.yml` 设置 `webrtcAdditionalHosts: [公网IP]`。

**第 4 步（强烈建议）：HTTPS。** 在 3100 前加 Nginx/Caddy 反向代理提供 HTTPS 证书（WebRTC 在非 localhost 的 HTTP 页面上部分浏览器会限制能力）。示例（Caddy 自动证书）：

```
your.domain.com {
  reverse_proxy 127.0.0.1:3100
  reverse_proxy /zslive/* 127.0.0.1:8890
}
```

> **何时必须 TURN？** 服务器有公网 IP 且防火墙放开 UDP 时，通常 STUN 就够；服务器在 NAT 后（家庭宽带、内网机房）或 UDP 被限速/拦截时，必须 TURN 中继。不确定就都配上——TURN 只在直连失败时才启用，不影响局域网性能。

### 8.4 集群部署（master/worker，自动跨节点调度）

多台渲染服务器时，用集群模式把调度集中到一台 master，用户只需要访问 master 一个入口：

```
                    ┌────────────────────────┐
   用户浏览器 ──────▶│  master（管理节点）      │  3100 页面/API/调度
                    │  不跑 UE，只做节点管理    │
                    └──────┬────────┬────────┘
              内部API 3120  │        │
                    ┌──────▼───┐ ┌──▼─────────┐
                    │ worker 1 │ │ worker 2   │  每台跑：调度服务 + MediaMTX + UE 实例
                    │ 3100/3120│ │ 3100/3120  │  浏览器拿到会话后直连 worker 的 WS/WHEP
                    └──────────┘ └────────────┘
```

**部署步骤：**

1. **master 服务器**：`server/.env` 设置 `CLUSTER_ROLE=master`，并设置一个随机 `CLUSTER_TOKEN=（长随机串）`，重启调度服务
2. **每台 worker**：完整部署平台（调度服务 + MediaMTX + UE 程序，按单机方式），`.env` 额外设置：
   ```ini
   CLUSTER_ROLE=worker
   CLUSTER_TOKEN=（与 master 一致）
   CLUSTER_INTERNAL_PORT=3120
   NODE_ID=render-01          # 节点唯一标识（默认主机名）
   NODE_NAME=渲染节点1（4090）  # 显示名（可选）
   NODE_PUBLIC_HOST=192.168.1.20  # 浏览器可达的本机地址（默认 PUBLIC_HOST）
   ```
3. **master 后台** →「节点管理」→ 填写节点地址与内部端口添加节点（页面会显示 master Token 供核对）
4. 约 5 秒内节点状态变「在线」，首页程序列表即聚合所有节点的模板（卡片标注节点名）

**调度策略**：有该模板 READY 实例的节点优先（余量多者优先）→ 池未满的节点 → 都满则挑队列最短的节点排队。节点掉线自动摘除，会话创建失败自动切换候选节点。用户释放会话时，请求自动路由回会话所在节点。

**运维要点**：

- 模板、GPU 配额、预热数在各 worker 自己的后台配置（master 是纯控制面，不跑实例）
- master 的审计日志记录节点增删改；节点状态/容量/GPU 在「节点管理」页实时可见
- 扩容 = 新 worker 部署 + 后台添加节点，master 无需重启
- master 离线时各 worker 仍可独立服务（直接访问 worker 地址）

### 8.5 无公网 IP 的替代方案（VPN 网关 / 内网穿透）

服务器没有公网 IP 时（家庭宽带、内网机房），按优先级选择：

| 方案 | 适用 | 说明 |
|---|---|---|
| **云主机部署**（最推荐） | 预算允许 | 整套平台部署到云服务器（选 GPU 实例或 GPU 挂载），公网 IP 直接可用 |
| **Tailscale / ZeroTier 组网** | 少量固定用户 | 服务器与用户电脑都装客户端组虚拟局域网，按 8.2 局域网方式使用，零穿透配置 |
| **WireGuard 网关** | 企业自建 | 一台有公网 IP 的云服务器做 WG 网关，渲染服务器接入；浏览器也连同一 WG 网络。UDP 8189/49160-49200 在 WG 隧道内转发即可 |
| **frp 端口转发** | 临时演示 | 云服务器跑 frps，渲染机跑 frpc 转发 3100/8890；**注意**：WebRTC 媒体走 UDP 8189，frp 需单独转发 UDP 且 `PUBLIC_HOST` 要设为云服务器 IP，复杂场景不推荐 |

> VPN 方案下用户与服务器同处虚拟网，WebRTC 走隧道内直连，无需 TURN——这是内网部署避开 NAT 问题最省事的方式。

### 8.6 多机部署的另一种形态（每机独立，不组集群）

小规模场景也可以不组集群：每台服务器独立部署（各自是 standalone），业务系统把不同模板/不同用户分配到不同服务器地址。集群模式适合「统一入口 + 自动调度 + 按节点扩容」的需求。

## 十、常见问题（FAQ）

**Q1：浏览器看到黑屏/一直转圈？**
- 启动器「实例监控」看该实例是否「✔推流」。没推流 = UE 程序没起来或编码失败，看日志区
- UE 5.7 无限 GOP 问题平台已自动处理（模板附加参数无需关心）
- 确认浏览器能访问 8890 端口（防火墙）

**Q2：有画面但没有声音？**
- 模板音频编解码选 **PCMA**。AAC 在 WHEP 播放端不受浏览器支持

**Q3：键鼠操作 UE 没反应？**
- 模板里确认勾选「允许输入」
- 平台 v2.0 起已修复打包程序无窗口焦点导致的输入丢失——确保你的 UE 程序是用**最新版 StreamForge 插件**打包的

**Q4：调度服务起不来，日志出现 `NODE_MODULE_VERSION` 字样？**
- better-sqlite3 原生模块与 Node 版本不匹配。解决：在 `server` 目录执行 `npm rebuild better-sqlite3 --build-from-source`，或改用安装时的 Node 大版本

**Q5：端口被占用？**
- 3100 被占：编辑 `server/.env` 改 `PORT`，并同步改启动器旁 `launcher.config.json`
- 8890/1935 被占：编辑 `mediamtx/mediamtx.yml`

**Q6：能开几路实例？**
- 取决于 GPU：1080p 下 RTX 3060 约 3~5 路，RTX 4090 / A 系列更多。在系统设置调「最大并发实例数」，观察实例 FPS 是否掉帧来找到甜点位

**Q7：服务器重启后怎么恢复？**
- 勾了「开机自启」则登录后自动拉起；未勾选则双击启动器即可

**Q8：数据在哪？要备份什么？**
- 全部数据在 `server/data/zslive.db`（模板、用户、会话记录）。备份这一个文件即可
